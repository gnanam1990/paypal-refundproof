# Delivery workflow

The proposed destination is the new private repository `gnanam1990/paypal-refundproof`; no repository is claimed to exist. At implementation intake, verify the authenticated GitHub owner and obtain separate authority before remote creation. Record the pre-build head and dirty state. Use one focused branch and one reviewed commit per completed module; never rewrite unrelated history.

Before proposing a PR, run formatting, static analysis, unit/property tests, database migration tests, integration tests, browser/accessibility checks, sandbox end-to-end recovery, production build, secret scan, and clean-checkout reproduction. The reviewed SHA must equal the tested SHA.

A PR body must state implemented requirements, actual commands and results, sandbox evidence, known gaps, migrations, rollback, security impact, and screenshots or video captured from the real product path. Push, PR creation, review requests, merge, deployment, public repository visibility, video publication, and hackathon submission require explicit separate authorization.
