# Master implementation prompt

Build RefundProof as a real sandbox-backed product. First inspect repository instructions, current branch, dirty files, toolchain, and existing architecture. Preserve user changes. Confirm the proposed stack against the repository before installing anything.

Treat `CORE-CONTRACT.md` as authoritative. Implement modules M00 through M05 using test-driven development. Before each fix, capture a failing test. After each module, record commands, exit codes, test counts, redacted runtime evidence, exact commit SHA, and unresolved risks. Never mark a test passed without running it.

The AI may extract, match, classify, and explain; deterministic code owns authorization, amounts, identity, execution, and provider finality. The central path must use PayPal sandbox. A timeout is unknown. An approval applies only to its exact revision. No hard-coded success, manual database repair, or mocked provider may satisfy acceptance.

Keep credentials out of prompts, client bundles, logs, commits, fixtures, screenshots, and videos. Stop on missing sandbox access, incompatible API behavior, ambiguous authorization, destructive migration risk, or a contradiction with repository rules. Report the blocker and preserve completed work.

Local focused commits are allowed when this prompt is explicitly invoked in the intended repository. Do not push, create or merge a PR, deploy, spend, publish, accept contest terms, or submit without separate user authorization.
